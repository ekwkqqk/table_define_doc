| 항목 | 내용 |
|------|------|
| 문서명 | 테이블 정의서 자동 생성 시스템 기능 정의서 |
| 버전 | 0.2 |
| 작성일 | 2026-10-10 |
| 상태 | 결정 사항 반영 (검토 중) |

---

## 1. 개요

### 1.1 목적
로컬(또는 접근 가능한) 데이터베이스의 메타데이터를 웹 UI에서 조회·선택하고, 표준화된 **테이블 정의서**를 생성·내보내기할 수 있는 시스템을 제공한다.

### 1.2 배경 / 문제
- 테이블 정의서를 수작업으로 작성하면 실제 DB 스키마와 불일치하기 쉽다.
- 스키마 변경 시 정의서 갱신이 누락되기 쉽다.
- DB 클라이언트마다 메타 조회 방식이 달라 산출물 형식이 제각각이다.

### 1.3 목표
1. DB에 연결해 스키마/테이블/컬럼/키/인덱스/코멘트 등을 자동 수집한다.
2. 수집 결과를 사람이 읽기 쉬운 테이블 정의서 형태로 보여준다.
3. Excel / Markdown 등으로 내보낸다.
4. 동일 연결·동일 선택 범위로 재생성하여 최신 스키마를 반영한다.

### 1.4 범위 (Scope)

| 구분 | 포함 | 제외 |
|------|------|------|
| 대상 | 테이블 메타데이터 기반 정의서 | 뷰·프로시저·함수·트리거, 데이터(행) 조회·수정 |
| 사용자 | 개발자 / DBA / 문서 담당자 (로컬·단일 사용자) | 로그인·역할·멀티테넌트 |
| 배포 | 로컬 백엔드 + 브라우저 UI | 데스크톱 셸(Electron 등), 퍼블릭 SaaS |
| UI 언어 | 한국어 | 다국어 |
| 문서 | 본 문서의 표준 정의서 양식 | 사내 커스텀 템플릿 엔진(후순위) |

## 3. 용어

| 용어 | 설명 |
|------|------|
| 연결(Connection) | DB 접속 정보 단위 (호스트, 포트, DB명, 계정 등) |
| 스키마/카탈로그 | DBMS별 네임스페이스 (PostgreSQL schema, MySQL database 등) |
| 메타데이터 | 테이블·컬럼·제약·인덱스·코멘트 등 구조 정보 |
| 테이블 정의서 | 테이블 단위로 정리된 문서 산출물 |
| 스냅샷 | 특정 시점의 메타데이터 수집 결과 |
| 오버레이 | DB에 없는 수동 보완 항목(업무 설명, 비고 등) |
| 데이터 디렉터리 | 연결정보·스냅샷·설정이 저장되는 로컬 경로 |

## 4. 사용자 / 이해관계자

| 역할 | 기대 행동 |
|------|-----------|
| 개발자 | 연결 → 테이블 선택 → 정의서 확인 → 내보내기 |
| DBA | 스키마 정합성 확인, 코멘트·키 정보 점검 |
| 문서 담당 | 정의서 확인 후 Excel/Markdown으로 배포 |

로그인·권한 체계는 두지 않는다. 백엔드는 신뢰된 로컬/사내망에서만 기동하는 것을 전제로 한다.

---

## 5. 전제 / 제약

1. 대상 DB는 백엔드가 네트워크(또는 소켓/파일)로 접근 가능해야 한다.
2. 메타데이터 조회에 필요한 DB 계정 권한이 있어야 한다.
3. 브라우저는 UI만 담당하고, **백엔드가 DB에 접속**한다.
4. 비밀번호는 화면에 평문 재표시하지 않으며, 저장 시 보호한다.
5. DBMS별 차이는 어댑터로 흡수하고, UI·정의서는 공통 모델로 정규화한다.
6. 인증이 없으므로 백엔드 포트는 기본적으로 `localhost` 바인딩을 권장한다.

## 6. 지원 DBMS

| DBMS | 연결 방식 요약 | 비고 |
|------|----------------|------|
| PostgreSQL | host/port/database/user/password | schema 단위 탐색 |
| MySQL / MariaDB | host/port/database/user/password | database ≈ 스키마 |
| SQLite | 파일 경로 | 사용자/비밀번호 없음 |
| Microsoft SQL Server | host/port/database/user/password | schema 단위 탐색 |
| Oracle | host/port/service(또는 SID)/user/password | 소유자(schema) 단위 |

구현 순서는 기술 설계에서 정하되, **제품 요구 범위에는 5종 모두 포함**한다.

### F-01. DB 연결 관리 [P0]

**설명**  
DB 접속 정보를 등록·수정·삭제·테스트한다.

**입력**
- DBMS 종류 (PG / MySQL·MariaDB / SQLite / MSSQL / Oracle)
- 연결 표시 이름
- 호스트, 포트, 데이터베이스(또는 서비스명/SID), 사용자명, 비밀번호
- SQLite인 경우 파일 경로
- (선택) SSL·추가 JDBC/드라이버 옵션

**처리**
- 연결 테스트: 실제 접속 후 성공/실패, 서버 버전 반환
- 연결 정보는 데이터 디렉터리에 저장 (비밀번호 암호화)

**출력**
- 연결 목록, 테스트 결과

**예외**
- 인증 실패, 타임아웃, DB 미기동, 권한 부족 → 한국어 오류 메시지

---

### F-02. 스키마 / 테이블 탐색 [P0]

**설명**  
선택한 연결에서 스키마(또는 동등 개념)와 **테이블** 목록을 조회한다.

**처리**
- 스키마 목록 조회
- **BASE TABLE만** 조회 (VIEW·MATERIALIZED VIEW 등 제외)
- 테이블명 검색·필터
- 다중 선택

**출력**
- 트리 또는 리스트 UI (한국어)

---

### F-03. 메타데이터 수집 [P0]

**설명**  
선택된 테이블들의 상세 메타데이터를 수집해 내부 모델로 정규화한다.

**수집 항목 (공통)**

| 구분 | 항목 |
|------|------|
| 테이블 | 스키마, 이름, 테이블 코멘트/설명 |
| 컬럼 | 순서, 이름, 데이터 타입, 길이/정밀도/스케일, NULL 허용, 기본값, 컬럼 코멘트 |
| 키 | PK, FK(참조 테이블·컬럼), UNIQUE |
| 인덱스 | 인덱스명, 컬럼, 유니크 여부 |
| 기타 | Identity/Auto Increment, Generated 여부(가능 시) |

**처리**
- 다건 테이블 일괄 수집
- 수집 시각·연결 정보를 스냅샷 메타로 기록

**예외**
- 일부 테이블만 실패 시: 성공분 유지 + 실패 목록 표시

---

### F-04. 테이블 정의서 화면 [P0]

**설명**  
수집된 메타데이터를 **15절 표준 양식**으로 화면에 표시한다.

**요구사항**
- 좌측 테이블 목록 / 본문 정의서
- 테이블 간 이동
- 긴 목록 스크롤·헤더 고정
- DB 코멘트 → 설명 칸 자동 반영
- UI 문구 한국어

---

### F-05. 수동 보완(오버레이) [P1]

**설명**  
DB에 없는 업무 설명·비고를 입력하고, 재수집 후에도 유지한다.

**처리**
- 키: `연결 ID + 스키마 + 테이블 + 컬럼`(또는 테이블)
- 재수집 시 동일 키면 병합
- 컬럼 삭제/이름 변경 시 미매칭 항목은 “매칭 안 됨”으로 표시

---

### F-06. 내보내기 [P0]

**설명**  
선택 범위의 정의서를 **15절 양식**으로 파일 출력한다.

**MVP 포맷**
- Excel (`.xlsx`)
- Markdown (`.md`)

**P1 포맷**
- HTML (인쇄용)
- PDF

**옵션**
- 선택 테이블만 / 현재 스냅샷 전체
- 인덱스·제약 섹션 포함 여부

---

### F-07. 재동기화 [P0]

**설명**  
동일 연결·선택으로 메타데이터를 다시 읽어 정의서를 갱신한다.

**MVP**  
전체 재수집 + (P1) 오버레이 병합

**P1**  
추가/삭제/타입 변경 컬럼 하이라이트

---

### F-08. 문서 설정 [P1]

**설명**  
정의서 표지·헤더에 들어갈 문서 정보를 설정한다.

**항목**
- 시스템명, 문서 버전, 작성자, 작성일
- 회사/팀명

---

### F-09. 데이터 저장 위치 설정 [P0]

**설명**  
앱이 사용하는 로컬 데이터 디렉터리를 관리한다.

**기본 경로 (OS별 관례)**
- Windows: `%APPDATA%\table-define-doc\`
- macOS: `~/Library/Application Support/table-define-doc/`
- Linux: `~/.config/table-define-doc/`

**저장 내용**
- 연결 정보, 스냅샷 캐시, 오버레이, 문서 설정, 앱 설정

**사용자 지정**
- 설정 화면에서 데이터 디렉터리 경로 변경 가능
- 변경 시: 새 경로 사용(기존 데이터 이전 여부는 확인 다이얼로그)

---

## 8. 화면 구성 (정보 구조)

```
[연결 관리]
   └─ 연결 추가/수정/테스트/삭제

[탐색]
   └─ 스키마 → 테이블 다중 선택 → [정의서 생성]

[정의서 워크스페이스]

   ├─ 중: 테이블 정의서 본문 (표준 양식)
   ├─ 우/모달: 설명·비고 편집 (P1)
   └─ 상단: 재동기화 / 내보내기 / 문서·저장 설정
```

모든 화면 라벨·메시지·버튼은 한국어.

## 13. 성공 기준

1. 지원 DBMS 5종 각각에 연결해 테이블 목록을 볼 수 있다.
2. 선택한 테이블의 정의서를 표준 양식으로 화면에 표시한다.
3. Excel / Markdown으로 내보낼 수 있다.
4. 재동기화 후 스키마 변경이 반영된다.
5. UI가 한국어이며 로그인 없이 사용 가능하다.
6. 데이터 디렉터리를 기본 경로 또는 사용자 지정 경로에 저장할 수 있다.

## 15. 표준 테이블 정의서 양식

사내 표준 양식이 없으므로 아래를 시스템 기본 양식으로 한다.

### 15.1 문서 헤더 (내보내기·표지)

| 항목 | 내용 |
|------|------|
| 문서 제목 | 테이블 정의서 |
| 시스템명 | (문서 설정) |
| 문서 버전 | (문서 설정) |
| 작성자 | (문서 설정) |
| 작성일 | (문서 설정 또는 내보내기 시각) |
| 대상 DB | DBMS 종류 / 연결 이름 / DB명 |
| 수집 시각 | 스냅샷 시각 |

### 15.2 목차 (다건 내보내기 시)

- 스키마.테이블명 목록 + 페이지/시트 링크(가능 시)

### 15.3 테이블 단위 본문

#### (1) 테이블 개요

| 항목 | 내용 |
|------|------|
| 스키마 | |
| 테이블명 | |
| 테이블 설명 | DB 코멘트 (+ 오버레이) |

#### (2) 컬럼 정의

| No | 컬럼명 | 데이터 타입 | NULL | PK | FK | 기본값 | Identity | 설명 | 비고 |
|----|--------|-------------|------|----|----|--------|----------|------|------|
| 1 | ... | varchar(50) | N | Y | | | | ... | |

- **NULL**: `Y` / `N`
- **PK / FK / Identity**: 해당 시 `Y`, 아니면 공란
- **FK**: 참조가 있으면 비고 또는 FK 열에 `참조스키마.참조테이블.컬럼` 표기
- **설명**: DB 컬럼 코멘트 우선, 없으면 공란(P1에서 오버레이로 보완)

#### (3) 제약조건

| 제약명 | 종류 | 컬럼 | 참조 | 비고 |
|--------|------|------|------|------|
| | PK / FK / UNIQUE | | | |

#### (4) 인덱스

| 인덱스명 | 유니크 | 컬럼 | 비고 |
|----------|--------|------|------|
| | Y/N | | |
